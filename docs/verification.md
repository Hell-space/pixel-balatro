# 1.2.0 验证记录

日期：2026-11-06。环境：Windows、Node.js 24.18.0、Python Playwright、已安装的夸克浏览器。浏览器使用无头隔离会话和模拟触摸，没有操作个人浏览器资料或安装新软件。

## 规则与服务器自动化

`npm test` 的 11 组测试通过，具体包括：

- 九种常规牌型、A2345、踢脚牌、万能同花、升级与燧石。
- 五条 1980 分、同花葫芦 2534 分、同花五条 3280 分的独立固定样例。
- 全部 41 种小丑各自的确定性计分样例；计算不修改输入。
- 两张摄影师 + 红封 K 为 400 分；两张黑客 + 两张黄昏 + 红封 2 在最后一次出牌为 17 分。
- 小丑换序改变乘法顺序；钢铁红封、黄金、随机倍率范围和花色 Boss 禁用万能牌。
- 主动离开释放房间、无效请求处理、仅房主能开始、断线宽限、Last-Event-ID 消息补发和重试去重。单元测试将宽限设为 200ms，浏览器测试使用正式的 30 秒。

## 正常浏览器流程

常规回归通过 390×844、360×640、844×390、1365×768，包含开局、最多 5 张选牌、长按、弃牌、逐手计分、首关结算、商店购买、下一盲注、教程、失败恢复及独立 HTML。

固定种子下真实打出两对 116 分与葫芦 296 分，合计 412 分通过首盲。测试独立计算这些普通牌的预期分数，没有修改游戏状态达成首关胜利。

新版还通过：

- 商店卡包购买、取消退款、原候选重开，以及选择中途刷新。
- 在满消耗槽状态下，从持有牌弹窗使用星球、购买新牌、出售塔罗，并刷新确认保存。
- 普通 1.1.0 存档，以及旧版通过「审判」生成的缺省 ed 小丑存档，都能正常继续。
- 主存档 JSON 或牌点损坏后恢复有效备份；卡包活动副本可由规范候选修复，规范候选损坏会回退备份。
- 模态窗口与嵌套卡包窗口的 Tab 不会进入背后的牌桌。
- 计分速度 1×/2×/4×/立即的结果一致，设置刷新后保留；音乐与音效 gain 独立变化。
- 正常失败 43 分后刷新、保留旧局、确认新局、回保存点及再次刷新。

## 联机实测

两个隔离浏览器会话通过本地 Node 服务完成：

- 创建/加入、同步对手状态；连续点击创建只发一次请求。
- 请求响应延迟时先取消，迟到的返回会清理房间，不重新连接。
- 已建房间取消后，另一客户端不能继续加入。
- 使用本地透明代理真正切断已建立的 SSE 流，短时恢复后继续同一局并出牌，同步对手得分。没有仅凭模拟 offline 标志断言连接已断开。
- 超过正式 30 秒宽限后结算、返回并重建；主动离开即时通知对手。
- 取消离开后仍可继续；确认离开后返回标题，可恢复多人之前的单人存档。

## 最终构建与限制

完整常规回归使用 141487 字节的构建。最后仅调整短屏菜单布局和触摸高亮，便携文件变为 141697 字节；按改动范围复验 320×568 菜单无需滚动且返回可点、390×844 选两张牌的预览。之后服务器请求体改为合并字节后统一解码，Node 回归再次通过；该改动不影响 HTML。

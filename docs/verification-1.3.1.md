# 1.3.1 商店与视觉验证

日期：2026-11-06。本轮不改变卡池、计分规则、商店价格或存档格式。

## 问题与修复

真实触摸复现了商店点击持有小丑后的异常：详情约 4ms 内已打开，但与商店同为 z-index 50；商店在 DOM 后面，盖住详情。视觉层级和实际命中不同，用户甚至能触发看不见的出售确认。修复后按打开顺序统一绘制、焦点和指针层级，并限制只有详情在顶层时才能出售。

原版商店买牌后，在 320×568、390×844、640×360 下分别存在约 398、68、522px 的整页滚动。新版改为小丑、消耗牌、卡包、优惠券四分类，库存和底部操作常驻。初次修复仍因旧选择器额外增加间距导致满槽消耗牌被挡，已删除该旧规则；验收使用每张持有牌五个位置的命中检查，不能只凭容器无滚动判定。

界面沿用绿毡、纸牌与黄铜色，重新整理商店纸卡、持有小卡、详情、计分区和按钮。角标改为与牌内花色一致的 SVG。新增出牌移到桌面、弃牌离场、逐牌筹码和购买入槽反馈；特效不消费游戏随机数、不改结算、不等待动画完成后才响应操作。1× 计分首尾停顿共缩短 350ms。

## 已完成验证

`npm test` 18 组全部通过。没有重新跑 1.3.0 的 216 局平衡模拟，因为本轮未修改经济、卡池或计分规则。

浏览器为独立的无头夸克环境，使用真实触摸输入，未使用个人浏览器资料。

- 180,368 字节阶段：三个手机尺寸正常首盲、购买、四分类切换、刷新、打开详情、取消、两次确认出售及刷新续局通过。另以明确的白盒夹具覆盖 6 小丑＋3 消耗牌、长效果文本和每张卡的边缘命中；持有区与底部操作均完整可见，整页滚动为 0。
- 同阶段以 1× 速度捕获选牌、弃牌、出牌、计分筹码、购牌入槽的中间帧，检查动画确实运行、结束后没有残留装饰节点。独立预期、预览和实分一致；减少动态和立即计分模式跳过计分飞行动画。菜单、图鉴与开包的层级/命中通过。
- 随后发现小屏 SVG 角标与牌内花色相交，以及弃牌复制节点丢失红/黑颜色；分别缩小角标墨迹、保留原卡状态 class。
- 最终 180,518 字节阶段：320×568、390×844、640×360 的 A/K/10 和数字牌无花色碰撞；390 预览/实分均为 16。实际弃出红色 K♦、黑色 J♣，中间帧保留原色，节点不可聚焦并正常清理；随后 1× 打两张 10，独立预期、预览、实分均为 60。

原始证据保留在忽略的 `.qa/v131/`；商店、动画和牌面检查分别对应 `visual-final-shop`、`visual-final-motion`、`final180518-motion`、`final180518-corners`。前两项之后只修改角标和弃牌颜色，因此没有把旧阶段证据描述为全部最终字节重跑。

仓库浏览器测试已适配分类入口；没有分类按钮的 1.1/1.2 页面仍沿用原操作。最终版卡包取消、开包刷新恢复、满槽消耗牌购买和损坏卡包恢复四项通过，360×640 正常单局通过；旧版 1.1/1.2 与新版均以真实触摸完成消耗牌购买和打开、取消卡包。原 smoke 只等分数变化便刷新，提前显示总分后会早于补牌完成，现已等待计分结束再比较续局手牌。

可复用的 `tests/browser_shop.py` 默认运行商店验收；`tests/browser_motion.py` 检查动画中间帧、红黑弃牌颜色、预览与实分、动画清理及减少动态。最终版额外执行 `focused_ghost`、`reduced` 两项通过。兼容与脚本维护证据在 `compat-final`、`compat-probe`、`compat-motion`。
